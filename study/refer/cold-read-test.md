# 冷读测试：一个陌生人能不能在几步内找到答案

**目的：** 检验 `eval/README.md` 这个"唯一入口"是否真的好用。找一个**没见过这个项目**的新会话（GPT 或 Gemini 都行），只告诉它从 `eval/README.md` 开始，看它能不能找到 5 个问题的答案，以及用了几步。它同时是"陌生人复现"的一个便宜的替身，**但不是**真人陌生人复现，不能当作它来声称。

## 做法

1. 开一个**全新的会话**，不要带任何本项目的上下文。
2. 让它能读仓库（本地克隆，或给它 GitHub 地址）。
3. 把下面"给对方的提示词"整段贴过去。
4. 把它的回答原样保存，对照最后的"标准答案"打分。**标准答案不要给它。**

## 给对方的提示词

```
你是第一次看到这个代码仓库的人，没有任何背景。请只从 eval/README.md 开始读，需要时再打开它链接到的文件。
不要看 git 历史，不要运行任何命令，不要调用任何模型，也不要猜：找不到就说找不到。

请回答下面 5 个问题。对每一题，请给出：
  (a) 你的答案，一两句话，并引用你依据的那句原文的文件名；
  (b) 你为了找到它依次打开了哪些文件（按顺序列出）；
  (c) 你对这个答案有多确定（高／中／低），以及哪里让你困惑。

问题：
1. 这个评测的主要结果是什么？（给出具体数字，并说明是哪一轮、比较的是什么。）
2. 我想自己验证这些数字，而且不想花钱调用模型，应该怎么做？
3. 这个项目明确没有声称什么、做不到什么？（至少三点。）
4. 评测的标签是谁、用什么模型标注的？这对结论有什么影响？
5. 如何复现？分几级？每一级证明什么、不证明什么？

最后请再回答：
6. 这个仓库的文档结构里，让你最困惑或最想删掉的三处是什么？
7. 你有没有发现两处文档互相矛盾的说法？如果有，列出文件和原话。
```

## 评分（只给你自己看，不要给对方）

每题满分 2 分：答对且在 3 步（打开 3 个文件）以内找到得 2 分；答对但超过 3 步得 1 分；没找到或答错得 0 分。**总分低于 8 分，说明入口还需要改。** 第 6、7 题不计分，但要认真读：它们是真实的陌生人视角。

| 题 | 应当答出的要点 | 应当找到的位置 |
|---|---|---|
| 1 | 第一轮：300 条合成记录，固定提示词两次运行各 300/300，34 个家族不是 300 个场景；关键词规则 R1 漏停 14、R2 漏停 10，是对照，不是优化前后。第二轮：180 条备注理解题，模型 173/180（96.11%），规则 R3 77/180（42.78%），同题对照 | `report.md`、`experiments/note_vs_rules_v2/RESULTS.md` |
| 2 | 第一级免费离线：在 `eval/formal/results` 里用 `shasum -a 256 -c SHA256SUMS` 核对哈希；跑测试（不联网、不要密钥）；第二轮原件公开，可免费复算 | `REPRODUCE.md`、`experiments/note_vs_rules_v2/evidence/README.md` |
| 3 | 没有专家标注（AI 标注和 AI 复核）；没有实车和制动验证；不是优化前后的提升；300 条不是 300 个独立场景；Safety 和 Compiler 的运行只测可用性，不是安全性评测；陌生人复现和口头验收没做 | `LIMITATIONS.md`、`docs/STATUS.md` |
| 4 | 第一轮：作者、盲标、复核、裁决都是 GPT 家族（不同会话），所以一致不是跨家族验证；第二轮：作者是 Gemini，标注和复核是 GPT 家族。来自会话元数据和自述，不是数据文件字段 | `ANNOTATOR_PROVENANCE.md`、`LIMITATIONS.md` 第 23 条 |
| 5 | 三级：免费离线、公开开发集实测、私有正式数据复现；第一轮逐条原件已丢，第三级无法做；复现不等于真人陌生人验收 | `REPRODUCE.md`、`LIMITATIONS.md` 第 22 条 |
