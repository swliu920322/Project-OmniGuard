# 指令文件的最佳实践（活文档，随使用迭代）

官方怎么说、加载机制是什么，见 [claude-code-memory-and-context.md](claude-code-memory-and-context.md)（稳定的事实）。**这份是我们自己的做法和度量，会变。** 每次改了 `CLAUDE.md`，或发现 AI 因为指令缺失或被忽略而出错，就在最后的迭代日志里加一行。

## 一、东西放哪

| 这条信息… | 放哪 | 例子 |
|---|---|---|
| 几乎每次对话都要用，读代码读不出来，不告诉就会做错，相对稳定 | 根目录 `CLAUDE.md` | 命令、冻结文件、不许调模型、检查失败时停下 |
| 只在某个目录里工作时才需要 | 那个目录的 `CLAUDE.md`（碰到该目录的文件才读） | 只和 `eval/` 有关的措辞规则（现在不拆，见第四节） |
| 多步骤、很少用、一次要好几步 | skill（描述常驻，正文触发才读） | "做一次真实模型运行"：授权、上限、健康检查、封存、回执 |
| 会变的事实：结果、数字、状态、进展 | 文档加测试，**不放** `CLAUDE.md` | `RESULTS.md`，`tests/test_round2_numbers.py` |
| 代码怎么走 | 代码本身和 `docs/guide/` | 请求路径 |
| 怎么走到这一步的 | 提交说明和 git 历史，不新建文件 | 设计取舍 |
| 跨项目的个人偏好 | 用户层记忆 | "改动前先给审计卡" |

## 二、怎么写一条规则

1. 写成 **"当 X 时：做 Y。由什么检查"**。没有自动检查就写 `No automatic check`，不要假装有。
2. 一条规则只说一件事；用真实的路径和命令，不写"相关文件"。
3. 不写读代码就能得到的叙述（会过时，官方也明确列为不该写的）。
4. 同一条规则被 AI 反复忽略时，**不要加粗、不要重复**，把它变成测试或钩子。这是文章里"关键规则写两遍，一遍说明，一遍机械检查"的意思。
5. 给人看的维护说明放 `<!-- ... -->`，官方说它在注入前被去掉，不占 token。

## 三、仓库里已有的机械防护（`tests/test_claude_md.py`）

| 检查 | 防什么 |
|---|---|
| 大小绊线 7 KB、60 行 | 慢慢变长。这是有意选的数字，不是官方要求（官方建议 200 行） |
| 提到的 `make` 目标、路径都存在 | 文档指向不存在的东西 |
| 每条规则都写 `Checked by` 或 `No automatic check` | 把没有保护的规则写成好像有保护 |
| 说"冻结"的文件确实在冻结清单里 | 说法和清单不一致 |
| 自检：给一份有错的假文本，检查必须报错 | 检查本身是空的 |

## 四、现在最值得做的优化（按收益排序）

数据来自 2026-11-21 的 `/context`：`CLAUDE.md` 约 3k tokens（0.3%），skill 描述 5.9k（0.6%），对话消息 875k（87.5%），其中命令输出 180k（18%）。

| # | 做什么 | 预计收益 | 成本和风险 |
|---|---|---|---|
| 1 | **限制命令输出**：用 `head`、`tail`、`grep`，大文件用带范围的读取，不要整份打印 | **最大**：这个会话里命令输出占 18%，约 90k 可省 | 是 AI 的行为，不是文件。可以在 `CLAUDE.md` 加一行规则（`No automatic check`），要你点头 |
| 2 | **一个任务一个会话**，快满时主动 `/compact`，不等自动压缩 | 大：这个会话到 91% 才处理；压缩会丢早期细节 | 无 |
| 3 | 关掉不用的 skill：先 `/skills` 看，再按官方提到的 `/skill-doctor` 找该关的 | 小：最多约 5k tokens，约 0.5% | 53% 来自 claude.ai 同步，关的位置在账号侧；我没核实具体步骤 |
| 4 | "做一次真实模型运行"做成 skill | 中：这套流程我们摸索过一次，下次可以直接用；新增约 100 tokens 的常驻描述 | 要写一份约 60 行的流程，等真有下一次再做 |
| 5 | 子目录 `CLAUDE.md`（`eval/` 的措辞规则） | 小：现在 45 行远低于 200 行 | 多一个指令文件；规则长到约 100 行再做 |

不要做：用 `@path` 导入来拆文件（官方：不省上下文）；为了凑上限往里填内容。

## 五、怎么衡量

- 改完 `CLAUDE.md` **开新会话**（官方：会话中途改不生效），跑 `/context all`，记下 Memory files 一栏。
- 要看 skill 的常驻成本：`/doctor`、`/skill-doctor`。
- 要看哪些指令文件何时被加载：官方的 `InstructionsLoaded` 钩子。
- 同一个任务用不同写法各跑一次，比较 AI 是否出错；没有这个对比，"更短更好"只是猜测。
