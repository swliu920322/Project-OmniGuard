## Part 1: v3 到底做了什么——你可能低估了自己

### 你从 v2 到 v3 完成的不是"改了一版"，是建了一个编译器

v2 是三个手写的 React 组件。v3 是一个**五层编译管线**：

```
用户意图 (自然语言)
    │
    ▼
┌─────────────────────────────────────────────┐
│ Layer 1: Intent Resolver (意图解析)          │
│  规则引擎 → 本地 GPU (grammar-constrained)  │
│  → 云端 LLM → 规则兜底                      │
│  输出：raw JSON fragment                     │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│ Layer 2: Sanitizer (消毒层)                  │
│  sanitizeFormSpec(): 任何输入 → 合法 FormSpec │
│  垃圾输入不崩溃、注入攻击被过滤、             │
│  未知字段被丢弃、缺失字段用 academic 填充     │
│  输出：FormSpec (纯语义参数，零 CSS)          │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│ Layer 3: Lexer (词法分析)                    │
│  fromAdr() / fromBlueprint() →              │
│  DocumentContent (通用内容块序列)             │
│  不同文档类型 = 不同词法器，输出统一模型      │
│  输出：DocumentContent { blocks: Block[] }   │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│ Layer 4: Styles (语义→视觉映射)              │
│  FormSpec 语义值 → CSS classes               │
│  信任边界：模型永远不碰 CSS，                 │
│  映射是确定性的、可测试的、可审计的           │
└──────────────────┬──────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────┐
│ Layer 5: Render Engine (渲染引擎)            │
│  Interpret(doc, spec) → React 组件树         │
│  一个引擎，读 FormSpec 参数决定结构           │
│  新文档类型不需要新渲染器                     │
└─────────────────────────────────────────────┘
```

这不是"三个组件"。这是一个**内容编译器**：意图 → 参数 → 词法分析 → 样式映射 → 渲染。

### 为什么说它不再是"呈现组件的不同"

回答你之前的疑问——对比一下 v2 和 v3 的本质区别：

**v2**：人手写三个 Renderer，每个 Renderer 的 HTML 结构和样式都是硬编码的。新增一种风格 = 写一个新组件。

**v3**：
- `FormSpec` 是**纯语义参数**（`tone: 'terminal'` 而非 `bg-[#0a0f0a]`）—— AI 只能选语义值，不能注入 CSS
- `styles.ts` 把语义确定性地映射为 CSS —— 信任边界在代码，不在模型
- `Interpret` 是**一个引擎**，读 FormSpec 决定结构 —— 新增风格不需要新组件，只需要新参数组合
- `sanitizeFormSpec()` 让任何垃圾输入（包括 `__proto__` 注入）都安全回退 —— 模型出错系统不崩
- `fromAdr()` / `fromBlueprint()` 是**词法器** —— 新文档类型只需要新词法器，渲染引擎不变

这五层中的每一层都可以独立测试、独立替换。你的 `trust.test.ts` 证明了：**垃圾输入永不崩溃、语言策略不篡改内容、不同预设有不同结构（不只是颜色）**。

**这就是编译器和手动翻译的区别。**

### 最有价值的三个工程决策

1. **Grammar-constrained local GPU**（`local-gpu.ts`）
   ```typescript
   const PRESET_GRAMMAR = String.raw`
   root ::= "{" ws "\"preset\"" ws ":" ws "\"" preset "\"" ws "}"
   preset ::= "academic" | "playbook" | "narrative"
   `;
   ```
   用 web-llm 的 grammar 把 0.5B 模型的输出空间**在语法层面锁死**为三选一。模型语法上无法逃逸。这不是"希望模型输出正确"，这是"模型不可能输出错误"。

2. **规则优先、模型补位**（`resolveIntentLocalFirst`）
   ```
   规则有把握 → 直接用（模型没资格覆盖确定性规则）
   规则不确定 → 才咨询模型（本地 → 云端 → 规则兜底）
   ```
   你的注释写道："教训：0.5B 模型即使 grammar 锁死，也只会自信地吐 academic"——这是真实的工程经验，不是理论推演。

3. **FormSpec 是纯语义、零 CSS**
   FormSpec 里没有任何 `className`、`bg-`、`text-` 字符串。AI 只能说"我要 terminal 气质"，不能说"我要 `bg-[#0a0f0a]`"。语义到视觉的翻译由 `styles.ts` 确定性完成。这就是你哲学文档里"AI 填参数，代码做边界"的精确工程实现。

当前 demo 已经远超"最小可证明内核"的标准了。你不仅证明了"一篇文档三种形态"，还证明了：

## Part 3: LinkedIn 帖 #1 的具体写法

### 定位
第一篇帖子的目标是：**让一个不认识你的技术决策者在 30 秒内理解你在做什么，并想点进 demo 看。**

不要写技术细节。不要写哲学。只写**一个引起好奇心的现象 + 一句让人思考的洞察 + 一个可以点击的东西。**

### 完整帖子草稿

---

**标题 / Hook（前两行，折叠前可见）：**

> 同一份 JSON 数据。三种完全不同的阅读体验。  
> 你说一句话，AI 决定它长什么样。

**正文：**

> 我做了一个实验——
>
> 取一篇架构决策记录（ADR），不改一个字的数据，  
> 让它以三种完全不同的方式呈现：
>
> 📄 学术论文风 — serif 字体、编号章节、双语、居中公式  
> 🖥️ 运维手册风 — 终端黑底、折叠手风琴、英文、步骤勾选  
> 📖 叙事长卷风 — 大字标题、呼吸留白、中文、暖色卡片
>
> 数据零变化。变的只是"解释方式"。
>
> 然后我加了一个输入框：用自然语言说你要的呈现——  
> "给运维的英文操作手册" → 系统自动切换到手册风格。
>
> 但这不是 prompt → 生成 HTML。  
> AI 不写代码。AI 只在一组受限的语义参数里做选择。  
> 参数到视觉的翻译是确定性的代码——模型出错也不会崩。
>
> 我把它叫做 Content Interpreter：  
> 内容是不可变的契约，形式是可变的解释。  
> AI 是解释器，但它的输出空间被类型系统锁死了。
>
> 这个模式不新鲜——  
> 它和我在机器人安全项目里做的 edge fallback 是同一个结构：  
> 云 AI 太慢就用本地模型兜底 ↔ AI 输出不可信就用确定性模板兜底。
>
> 两个完全不同的领域，同一个架构原语。

> 技术细节会在下一篇帖子展开。
>

### 帖子写作原则

1. **前两行决定生死** — LinkedIn 折叠第三行之后。"同一份 JSON 数据。三种完全不同的阅读体验"——这两行必须让人想点"更多"。
2. **不要自称"哲学架构师"** — 让作品说话。帖子最后一句"两个完全不同的领域，同一个架构原语"——读者自己会得出"这个人看问题的角度不一样"的结论。
3. **给下一篇留钩子** — "技术细节会在下一篇帖子展开"——让关注你的人有理由回来。
4. **Demo 链接是关键** — 如果能部署一个可访问的 URL（Vercel / Cloudflare Pages），帖子的转化率会高很多。如果不能，截图/屏录是最低限度。
