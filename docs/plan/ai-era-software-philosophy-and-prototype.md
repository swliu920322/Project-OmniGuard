# AI 时代软件哲学与动态即兴原型构想
# AI-Era Software Philosophy & The Dynamic-Improvisation Prototype

> **类型**: 设计文档 / 哲学与原型规划
> **对应 ADR**: [ADR-035](../../adrs/ADR-035-%5Barchitecture%5D-Data-Contract-First-Multi-System-Productization.md)（数据契约优先，本文是其上层哲学延伸）
> **创建**: 2026-08-15  |  **状态**: draft

---

## 1. 一句话哲学 (The One-Line Thesis)

> **AI 时代软件的能力 = 把"解释器"从确定性代码，升级为"在受控类型上动态组装的 AI"；
> 把贵的部分推到用户侧，把判断留在契约里。**

传统/低代码是 **声明式 + 静态解释**（配置一次，永远那个样子）；
AI 时代是 **声明式契约 + 动态解释**（每次根据数据与意图重新组合）。

---

## 2. 五大支柱 (Five Pillars)

### 2.1 受限自由 (Constrained Freedom)
- **决策空间**：AI 可自由（怎么组织、怎么表达）。
- **输出空间**：严格受约束（schema / 状态机 / 权限 / 组件库）。
- 形式是"受限的自由组合"，不是无约束生成；生成结果永远是确定性回退的候选。

### 2.2 数据受控 (Controlled Data)
- 数据 / 契约 / 状态迁移是**类型**，AI 不许触碰。
- 所有 AI 输出必须过运行时契约校验（Zod）→ 失败则重试 / 降级 / 进入审查。
- 架构原则：**AI 触碰"形式"可自由，触碰"数据"必须过类型闸门。**

### 2.3 成本分层 (Cost Layering)
| 层 | 归属 | 成本 |
|---|---|---|
| 生成 / 创作 | 用户侧（BYO key / 本地模型 / 端侧） | 贵，用户承担 |
| 校验 / 规约 | 企业侧（规则引擎 + 小模型 + 审查流） | 便宜，企业承担 |
| 编排 / 呈现 | 契约驱动动态组合 | 趋零 |

企业侧只留"便宜的守门人"，把"昂贵的想象力"推给用户。

### 2.4 分布式个人智能 (Distributed Personal Intelligence)
- 按任务分层，而非按设备分类：
  **端侧(固定单任务) → 本机(个人上下文 + 常规生成) → 云(前沿重活)**。
- 分布式节点的真正价值是**个人上下文层**（隐私 / 持久化 / 无限上下文 / 零边际成本 / 低延迟），
  而不是算力农场（云算力永远更便宜）。
- 分档路由器（Smart Router）本身就是核心智能——对应 OmniGuard 运动学定理的延迟预算问题。

### 2.5 人机审查闭环 (Human-in-the-Loop Review)
- AI 提议、人裁决，作为一等公民 UX：提案 → diff → 确认/否决。
- 结构化生成 + 运行时校验 + 确定性回退 = 应对"AI 易错"的工程正解。

## 3. 原型构想：动态即兴 (Dynamic Improvisation)

> 载体：在云基础架构（Bicep / ACA / SWA / CDN，复用 Project-OmniGuard 基建）之上的**内容门户原型**。
> 用 OmniDocs 的 98 篇文档作为数据源——**manifest 是数据，形式是动态的**。

### 3.1 认知问题："怎么让人们知道？"
传统产品讲解靠文档/截图。AI 时代的"动态形式"无法用静态截图说明——
**必须让用户亲手感知"同一个内容，能长成不同的样子，而且是为我变的"。**

**核心展示策略 = 游戏化的比较体验 (Comparative Play)**
- 让用户**并排对比**同篇文档在两种风格/场景下的呈现（dark/light、学术/极客、极简/华丽）。
- 核心目标：让用户第一次意识到——**"页面是活的，而且是为我活的"**。
- 交互上给用户"自由度 + 反馈"：滑杆、一键变换、主题探索、当前风格标签。
- 视觉必须**凸显特色**（动画、质感、光影、反应性），因为"形式可变"本身就是待展示的产品能力。

> 游戏化的本质不是"做游戏"，而是**把"动态能力"具身化为用户可操作的体验**，
> 让用户在玩的过程中既理解能力、也暴露偏好。

### 3.2 原型范围 (MVP)
- 数据：`docs-manifest.json`（98 篇，契约驱动）。
- 呈现层：契约驱动的动态主题引擎（同一 manifest，多套视觉风格/信息密度/场景）。
- 交互：风格比较 + 预演 + 喜爱度反馈 + 当前风格标签。
- 部署：纯 SSG 门户（Cloudflare Pages / SWA / Azure Blob），运行时成本趋零。
- 可嵌入：Web Component `<omnidocs-viewer>`（对应 ADR-035 集成面矩阵）。

### 3.3 低成本高交互引擎 (Low-Cost High-Interaction Engine)

> 认知前提：Apple 式交互本质是"写死的脚本"，一页册手写一次——所以贵。
> 低成本的钥匙不是"写更多交互"，而是**把"手感"封装成统一运动语言 + 时间线编排层 + 主题参数注入**。

**核心判断**：高交互 ≈ 统一的物理运动语言（spring 弹性、滚动粘合、减速曲线），
而非特效数量。它统一 → 显得贵却浑然一体。所以：

> **之后每个页面不是"写动画"，而是"选原子 + 填参数 + 排时间线"。**

**交互原子库结构（复用 monorepo packages/* 模式）：**

```
packages/interaction/
├── primitives/    交互原子：reveal / parallax / magnetic / 3D-tilt / spring-number / marquee / scroll-progress…
├── timeline/      编排层：把原子串成时间线（scroll-driven 关键帧 + 缓动曲线）
└── theme/         风格参数 → 注入 props（连回 §4 偏好空间）
```

**三步降低成本：**
1. **站在成熟引擎上，不造轮子**：底层 Motion / GSAP + Lenis（滚动手感），Web Animations API 兜底。
2. **一次性封装原子库**：几千行投入，之后每页是"配置"而非"代码"。
3. **把固定脚本升级为数据驱动**（与 Apple 的本质区别）：时间线参数（速度/密度/滚动响应）
   **由数据 + 用户偏好向量注入**——滚动快慢、内容类型、此刻沉浸度都在改变运动参数。
   这才是真正"动态形式"，而非 H5 里一堆固定互动。

**这与哲学的关系 = "受限自由"的落点**：
> **AI 不写动画代码，AI 只生成时间线编排脚本（受 schema 约束），人来挑/改。**
> 编排层 = 契约，AI 生成 = 内容，引擎解释 = 形式 → 高交互、低成本、且可控。

### 3.4 业务驱动的动态语言方法论 (Business-Driven Motion Methodology)

> 动效不是"越多越好看"，而是有成本的**信息通道**。设计前必须先分类业务，
> 否则 dashboard 会被装饰性动效拖垮提醒价值，营销页会因克制而平庸。

#### 核心法则 (The Prime Law)

> **动效密度 ∝ 表达诉求 ÷ 信息负载。**

- 信息负载越高 → 动效越要克制，只做"变化通知"。
- 表达诉求越强 → 动效越可放开，做"沉浸叙事"。
- 任何动效必须先回答："它传递了什么状态/层级/因果？"答不出 → 砍掉。

#### 业务分类二维象限 (2×2 Business Taxonomy)

用两条轴切分所有业务：**信息负载**（认知密度）× **体验诉求**（功能性 vs 表达性）。

```
        表达性 (Expressive)
            │
   反馈/游戏 │ 营销/品牌
   (低信息)  │ (低信息)
────────────┼─────────────
   工具/效率 │ 内容/阅读
   (高信息)  │ (高信息)
            │
        功能性 (Functional)
```

| 业务类别 | 象限 | 动效角色 | 原子选择 | 典型示例 |
|---|---|---|---|---|
| 工具/效率 | 高信息·功能 | **变化通知** | spring-number / 淡入(≤150ms) / 状态点过渡 | Dashboard, Admin, IDE, 交易台 |
| 内容/阅读 | 高信息·表达 | **引导阅读** | reveal / scroll-progress / 锚点过渡 | 文档系统, 博客, 知识库 |
| 营销/品牌 | 低信息·表达 | **沉浸叙事** | parallax / timeline 叙事 / magnetic / 滚动场 | Landing, Campaign, 作品集 |
| 反馈/游戏 | 低信息·功能 | **反馈激励** | spring 弹跳 / 进度激励 / 完成态爆发 | Onboarding, Quiz, 小工具 |

#### 动态语言五法则 (Five Motion Laws)

1. **动效即信息**：motion = information channel。动效必须编码状态转移、
   层级关系或因果，否则只是噪声。
2. **惰性动效**：静止是默认，只有"变了的东西"才动。高信息界面的黄金法则。
3. **层级即物理**：交互层级用弹簧（spring），空间叙事用视差（parallax），
   介质决定缓动——让同一种手感贯穿全产品。
4. **时长知性**：变化通知 ≈120ms，转场 ≈240ms，叙事 ≈600ms+。
   大脑不等待：通知越短越好，叙事越长越沉浸。
5. **用户主权**：尊重 `prefers-reduced-motion`；正在阅读时禁用滚动驱动强动效。

#### Dashboard 专属章程 (Dashboard Doctrine)
> dashboard 处于盲区——它是全产品信息负载最高、却最容易堆动效的地方。

- **应该**：数值变化通知（spring-number 滚动到新值）、状态点过渡、
  告警脉冲（高频 120ms）、图表数据切换的交叉淡入（240ms）。
- **不该**：装饰性循环动效（旋转/呼吸）、视差滚动、磁吸 hover、
  华丽叙事时间线。这些会淹没真正的"变化信号"。
- **原则**：**动 = 事件或状态转移，静止 = 默认。**
  用户扫读 dashboard 时，任何运动都必须意识到："这里发生了什么变化"。

## 4. 用户建模：人很复杂，不能简单分成几种

### 4.1 核心判断
> **不要给"人"分类，要给"偏好"建向量。**

人是高维连续的，标签是偏好在某个轴的投影。从"你是哪一类人"改为
**"你的偏好目前靠近这个多维空间里的哪个点"**。

### 4.2 偏好空间设计 (Preference Space)
1. **连续权重标签，而非开关**
   每个风格标签是 `-1..+1` 的连续评分（如 `density: -0.6`、`colorfulness: +0.4`），
   组合成高维向量，而不是"喜欢黑/白"二选一。
2. **双层结构**
   - **稳定层（审美倾向）**：会话 / 产品跨期稳定——克制 vs 华丽，信息密度，动效偏好。
   - **情境层（当前状态）**：时刻变化——当下是要沉浸阅读、快速浏览、还是演示模式。
   两层都是向量，情境层是稳定层的临时偏移。
3. **显式 + 隐式信号融合**
   - 显式：用户点"喜欢/不喜欢"、选择对比偏好。
   - 隐式：停留时长、滚动深度、回访、切换频率。
   隐信号校准显信号，显信号解释隐信号（例如：停留久 ≠ 喜欢，可能是困惑）。
4. **冷启动：对比题优于问答题**
   让用户并排看两版并二选一（"这版更像你的菜吗？"），
   **一次比较 = 一次高信息量的偏好采样**，远比"你偏好什么风格？"准确。
   每个对比题的权重因子可预先设计（用偏好空间的各维度差异）。
5. **用户主权（受控）**
   偏好模型**对用户透明、可查看、可覆盖、可重置**。
   偏好向量存本机 / 用户侧（呼应 2.4 分布式哲学）；
   若上云，只上传匿名化的低维投影或差分隐私聚合。
   > 这本身也是"数据受控"哲学的体现——连用户自己的偏好模型都不例外。

### 4.3 从"类型"到"引导"
- 不用标签把用户钉死，而是用标签**计算下一个对比题 / 下一个推荐风格**。
- 每个阶段给用户最可能有分歧的两个选项，采集后收敛偏好点 → 动态适配形式。
- 方向是 **探索（explore）与利用（exploit）的平衡**，而非"归入某一类"。

## 5. 原型落地路径 (Roadmap)

| 阶段 | 内容 | 产出 |
|---|---|---|
| P0 | 本设计文档确认 + 数据源就绪 | 哲学落地，92% 文档已索引 |
| P1 | 交互原子库骨架 + 契约驱动动态主题引擎 + 并排比较交互 | 可感知"动态形式"的 MVP 门户 |
| P2 | 对比题偏好采样 + 双层偏好向量（本机存储） | 偏好收敛 demo |
| P3 | 隐信号融合 + 引导推荐风格 | 个人化形式适配 |
| P4 | 上云部署 + Web Component 嵌入 | 产品化闭环 |

## 6. 演进守则 (Evolution Rules)

- **先验证"感知"再验证"智能"**：P1 先让用户"看见动态"，再做偏好收敛。
- **偏好模型永远是用户可解释的**：任何标签建议必须能回放"为什么给你这个"。
- **不把用户归队**：营销上可以说"你喜欢经典极客风"，
  但系统内部永远是向量近邻，不是类别成员。
- **数据零上传默认**：除非用户显式开启云同步。
