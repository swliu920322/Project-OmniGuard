## 第一部分：我看到了什么

### 1. why-most-skills-are-garbage
- 主张：大多数 skill 是提示词收藏夹。判据：它有没有改变 agent 的行为，这个改变能否验证，没用时能否看出来。
- 作者的实验：5 次 × 5 类任务 × 2 条件 = 50 次，过程得分 62.84→88.72，隐藏测试通过率都是 20/25。另一个 40 次实验里过程分涨了而隐藏测试反而下降。结论：skill 只能证明更可审计，不能证明更正确。
- 垃圾 skill 的 7 个特征：没有触发场景、没有可观察输出、只写价值观、没有反例、不能被测试打脸、让 agent 更啰嗦但不更正确、不维护。
- 8 问检查表（过不了 5 条基本可删）：触发条件、输入输出、先做什么后做什么、失败处理、禁止事项、验证命令、已知坑、能否被 benchmark 打脸。
- 没看到：4 张图、"发布短版"、实验原始数据。

### 2. loop-engineering-codex
- 主张：从"每轮写提示词的人"变成"设计反馈闭环的人"。结论："Build the loop. Stay the engineer."
- 四层：Prompt、Context、Harness、Loop。
- 五条原理：agent loop 是闭环控制；模型会忘仓库不会忘；工具决定能力边界；模型不应单独验证自己；长任务失败多因上下文爆炸、状态丢失、文件冲突、停止条件不清。
- loop 八步：发现、分类、计划、在独立 worktree 执行、验证、人工评审、写状态、下一轮。
- 其他：`AGENTS.md` 章节、`.loop/` 目录、maker/checker 分离、不适合用 loop 的场景（目标不可验证、风险极高、需求没想清、缺测试、人审带宽不足）、七天落地路径。
- 没看到：引用的 OpenAI、Anthropic、Addy Osmani、Simon Willison 文章。

### 3. ai-native-first-principles
- 主张：六圈螺旋，从交一个任务到让团队也这么干；每圈一个顿悟一个装置。
- 要点：模型的奖励函数是"能跑"；模型给先验，事实给后验；一次生成不构成工作，闭环才构成；读并行、写收敛到一个人；评价机制比自主程度重要；十个超级个体不会自然变成一个超级团队。
- 装置：须知预算（≤8KB、≤60 行，用测试守住）、事实优先级链、状态写进文件、金丝雀、"还不知道"第三状态、评委要盲化、配对、异构。
- 原则："没有停止条件的 agent，不是自主，是失控。"
- 作者承认：维护成本高、给不出 ROI 数字、担心判断力无法长出来。
- 没看到：引用的 Chroma 论文、AgentRewardBench 等；我不知道引用是否准确。

### 4. harness-engineering
- 主张：agent 反复失败时，先看模型周围的系统，不要先改提示词形容词。"权重没变，变的是 harness。"
- 七项职责：请求变契约、给地图不给百科、工具有契约和边界、记忆外置、先装传感器再给自主权、权限在模型之外执行、留痕与局部恢复。
- 具体做法："关键规则写两遍"（说明加机械检查）；失败→改动映射表（"修类，不修例"）；有界循环；L0–L3 分级；"harness 应该比它要控制的失败面更小"；12 项上线前检查；变更回执。
- 没看到：12 项清单的完整原文、映射表的全部行。

### 5. ai-eval-harness
- 主张：Prompt 决定怎么做，Harness 决定怎么知道做对了没有。评测的是完整链路。
- 最小 harness 六部分：数据集、runner、parser、scorer（精确、规则、LLM 评委）、报告、golden cases。
- 原则：优先让模型输出结构化中间结果；评估集版本化；失败样例比平均分重要；用 harness 约束上线。
- 示例数字（120 条、通过 103、成本 3.42 美元）是页面的演示，不是真实实验。页面没有作者和日期。

### 6. mcp-mental-model
- 主张：MCP 是工具协议，不是 RAG。四类能力（Tools、Resources、Prompts、Sampling）；server 封装后端；模型只看 schema；多轮 tool-calling；价值是工具生态标准化。三个常见误区。
- 没有数字和清单，离本项目最远。

- **缺口：** 规范逐段是谁起草的未恢复（`ANNOTATOR_PROVENANCE.md` 第 9 项）。

### 第 2 关：题是谁出的，会不会偏向模型？（出题）

### 第 3 关：金标怎么来？（标注）

### 第 5 关：被测系统怎么约束模型？（系统设计）
- **会被问：** 模型出错了谁兜底？

- **文章规则（F）：** 模型提议、策略检查、工具执行，权限放在模型之外（Harness）；有界循环；harness 要比失败面小。
- **缺口：** **G6** `gate()` 在模型调用之后（`LIMITATIONS` 第 21 条已披露）。**G7** Safety 和 Compiler 没有不重试、有界的保证。
- **补法：** G6 **已做**（2026-11-21，在不冻结的 `extended.py` 里先判 gate，`decide()` 未改）；G7 **已实施**（2026-11-21，`bounded_agent.py`，假客户端测试；见 `LIMITATIONS` 第 24 条）。

## 三分钟怎么讲

1. 我做的是一个模拟的 AGV 决策系统加评测，不是车控。
2. 评测要回答一个问题：173/180 凭什么信？我把它拆成八关。
3. 前四关管数据：规范定义对错，作者出题，盲标复核裁决出标签，冻结防泄题。**我把"谁做的"也查清并写下来了，第一轮同家族，第二轮作者和标注者不同家族。**
4. 中间两关管系统：模型只提议，代码兜底；运行有预算和不重试。
5. 后两关管证据：独立复算、失败样例保留、原件公开可免费复算。
6. 我清楚的缺口有哪些：没有 canary 和第三状态、Safety 和 Compiler 没评测、没有陌生人复现。**每一个缺口都有一条补法和需要的授权。**
