# Known limitations (draft, status of 2026-11-07)

Written now so that nothing is discovered later and quietly left out. It lists what is already known; the limitations of the formal test will be added when it exists.

## About the task and the data
1. **A simulation.** All thresholds, priorities, actions and the turn range are experimental conventions of a cloud-edge AGV simulation. None comes from real equipment, a standard or field data.
2. **Synthetic and templated data.** The 180 dev records are generated by rules from a seed. The 72 notes are templates in three languages with numeric variants, not 72 independent scenarios. A model that reads the rules written in the prompt can do very well on such data (baseline B: every reply that came back was correct), so the dev set separates little. Whether the independent test set separates more is not known yet.
3. **AI labels, not expert truth.** The dev notes have now been blind-annotated on 33 of 96 noted items and all 96 reviewed. The final test notes have a sealed 24/72 blind sample and all 72 reviewed; all 20 noted test-side stress cases were independently annotated and reviewed. The blind samples agreed with the initial statuses, but both annotators are AI sessions and can share misreadings. High agreement establishes consistency with the specification, not external correctness. Test records form 34 conservative families; 300 records must not be described as 300 independent scenarios. Mandatory threshold/gate anchor designs are shared with dev by specification; other backgrounds and note scenarios were independently authored and audited. See `acceptance/FROZEN_MANIFEST.json`.
4. **Gold routes are rules.** Telemetry labels are computed by the specification's rules, so on telemetry-only records a rule reproduces the gold by construction. Agreement with the gold shows consistency with the written convention, not correctness against an outside truth.
5. **Old data is history.** The archived 200 rows (baseline A) have no independent support for `LOW_BATTERY`, `LOW_HEALTH` or `OVERSPEED` (all 51 old sensor-error rows are overheating) and 11 old "critical" rows sit at 30 to 50 cm. Baseline A's 96.5 % / 78.0 % describe the original implementation's router stage only, with legacy labels, and are not comparable with the historical 94.19 %.

## About the model and the measurements
6. **The model version is unverified.** The API returns only an alias (`deepseek-flash`); the configured name `deepseek-v4-flash` is no longer in the provider's model list. The version in every record is the owner's statement.
7. **A reasoning model.** It spends hidden reasoning tokens and ignored `max_completion_tokens=20`. Cost and latency include them. The requests carry `temperature=0`, but the provider documents that its default reasoning mode ignores temperature, so the temperature is **not** demonstrably controlled; reproducibility rests on the two-run agreement gate, not on the setting.
8. **Provider errors are part of the numbers.** Baseline B's dev run had 5 failed calls of 180 (four HTTP 500, one 503); they count as wrong and are not retried. Two baseline-B canaries failed with HTTP 500 and a later diagnosis could not tie the failures to any change in the request; the cause is not established (a service incident was showing on the status page, which makes a service-side cause plausible, not proven). Whether a formal run should treat such errors differently was fixed in advance: no retry, failures counted wrong, a success-only accuracy may be reported next to the main figure and never instead of it.
9. **Costs are estimates, not bills.** See the ledger in `EVIDENCE_INDEX.md`.

## About the backend path
10. **Fake dependencies.** The opt-in extended tenant's HTTP flow (Router, Safety, Compiler, action contract) is tested with fake models and a fake Cosmos. It has not been run end to end against a real model through the endpoint.
11. **`goal=CHARGER` is a structured goal.** Nothing checks a path or a destination; it is not evidence that a vehicle reaches the charger, and "return to charge executed" must not be claimed.
12. **The physical gate differs between paths.** The legacy path uses the endpoint's integer values; the extended path uses the evaluation's gate on the exact values. The IoT Hub path is not switched.
13. **The emergency stop is a flag.** It is a structured boolean from a separate entry, not something recognised from text; there is no real stop channel behind it in the simulator.

## About the rule controls
14. **R1 and R2 are weak baselines with disclosed failures**: the subject of a clause cannot be carried over ("刚才有人，现在走了"), and typos defeat the keywords (one missed halt in the dev stress cases). Their word lists were written by the author of the dev notes and extended once on the public examples; their dev numbers are offline results on dev material, not formal results and no evidence of generalisation.

## Not yet known (will become limitations or results)
- accuracy, macro-F1 and per-class recall of baseline B and of any optimised version on the **independent frozen test set**;
- behaviour of a real model on injection, typos and multi-clause notes at stress-test scale;
- run-to-run agreement on the test set; reproduction by a stranger.
