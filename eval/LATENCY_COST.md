# 延迟与成本证据（2026-11-07）

结论先说：**正式运行的公开结果里没有延迟字段，所以正式延迟的中位数和 P95 现在不能给出，也没有去猜。** 成本可以由公开文件算出平均值。下面分开写：能算的、不能算的、以及需要私有记录保管者补的字段。

## 1. 成本（能算，来源是公开文件）

来源：`formal/results/*/public_summary.json` 的 `usd_from_reported_usage` 与 `budget.tokens_committed`，合计见 [formal/results/VERIFICATION.json](formal/results/VERIFICATION.json) 和 [report.md](report.md)“用量与费用”。

| 范围 | API 请求 | 估算金额（US$） | 平均每次请求（US$） | 平均每次 token |
|---|---:|---:|---:|---:|
| 主测试第 1 跑 | 300 | 0.133227 | 约 0.000444 | 约 991 |
| 主测试第 2 跑 | 300 | 0.134626 | 约 0.000449 | 约 994 |
| 压力集（含 32 次真实请求，另有 23 例未调用 API） | 32 | 0.016121 | 约 0.000504 | 约 1,040 |
| 全部（含 2 次健康探测） | 634 | 0.284948 | 约 0.000449 | 约 995 |

计算口径：
- 平均值 = 金额（或 token）÷ 该范围内 API 请求数，只是**平均**，不是中位数；公开文件没有逐次金额，算不出中位数或分位数。
- 金额是**按配置费率的估算**（输入 0.3333334、输出 1.3333334 US$/百万 token，取 Flash 的保守高峰价），**不是账单**。提供方实际账单、折扣和缓存命中价都没有核对过。
- 用量含隐藏的推理 token（这是推理模型，见 [LIMITATIONS.md](LIMITATIONS.md) 第 7 条）。
- 压力集平均值分母是 32 次真实请求；23 例离线案例没有费用，不在分母里。

## 2. 延迟

### 2.1 正式运行：公开文件不足

公开的 `public_summary.json` 与 `report.md` 只含聚合指标、用量和费用，**不含逐次耗时**。逐次耗时在私有运行包里（调用记录里本来就记了每次请求的 `latency_ms`，但我没有读取私有目录，也不推测数字）。

需要私有记录保管者计算并交回的字段（只要聚合，不要逐条输入和回复）：

| 字段 | 说明 |
|---|---|
| 两次主测试的请求数 n，及其中成功返回的数量 | 分母要写清，失败请求另列 |
| 成功请求延迟的中位数、P95、最大值（毫秒） | 分位数口径写明，例如“最近秩法” |
| 全部请求（含失败）的中位数、P95 | 两种口径并列，不能只给成功的那种 |
| 压力集 32 次真实请求的同样几项 | 离线案例不计入 |
| 每个统计量的时间范围和提供方 | 说明是同一天、同一服务 |

交回后写成“Router 请求延迟”，并保留它不是端到端延迟的说明（见 2.3）。

### 2.2 开发集真实运行：公开，可以算，但只是旁证

`baseline_b/runs/20261107T075357Z_real_c5e026a8/calls.jsonl` 是公开开发集的真实运行（180 次，B-1.0，不是正式数字），每条都有 `latency_ms`。我按下面的口径算了一次：

| 口径 | n | 中位数 | P95（最近秩法） | 最大值 |
|---|---:|---:|---:|---:|
| 成功返回的请求 | 175 | 约 1.76 秒 | 约 2.65 秒 | 约 15.1 秒 |
| 全部 180 次（含 5 次服务端错误） | 180 | 约 1.76 秒 | 约 3.15 秒 | — |

这 5 次错误请求的耗时约 15.3 秒（其中 1 次 0.38 秒），它们拉高了全量口径的 P95。这一套数字只能当“数量级旁证”：
- 测的是**一个开发集下午的一次运行**，不是正式运行；
- 提供方、网络和当时的服务状态都会变，不能当作承诺；
- 这个运行的 5 次错误按预先约定计错、不重试。

开发集这次运行金额 US$0.078923，180 次请求，平均约 US$0.000438。

代码层面的计时起止点、等待云端时车辆如何移动、哪些数字是设定值，见 [LATENCY_EVIDENCE.md](LATENCY_EVIDENCE.md)。

### 2.3 Router 延迟不是 HTTP 端到端延迟

- 上面的延迟是**客户端对一次模型 API 请求计时**（从发出到收到完整回复，含推理 token 的生成）。
- **没有测过** `/api/simulate_agent` 的 HTTP 端到端延迟：扩展租户的完整流程（急停检查、输入检查、Cosmos、Router、Safety、Compiler 两次额外模型调用）从未对真实模型端到端跑过（[LIMITATIONS.md](LIMITATIONS.md) 第 10 条）。端到端延迟会包含 Safety 与 Compiler 的调用，不能由 Router 延迟推出。
- 历史文档里的“省约 6174 ms / 3191 ms”来自旧三类流水线的 200 次历史汇总，口径不同，不能与本文数字相加或比较（见 [../docs/architecture/README.md](../docs/architecture/README.md)）。

## 3. 能说与不能说

能说：“正式评测按配置费率估算共约 US$0.285（634 次请求），平均每次请求约 US$0.00045，这是估算不是账单；开发集一次运行中，成功请求的 Router 延迟中位数约 1.8 秒、P95 约 2.7 秒，正式运行的延迟尚未统计。”

不能说：正式运行的延迟数字（还没有）、端到端延迟、“低延迟”“实时”，以及任何由这些推出的吞吐量或上线成本。
