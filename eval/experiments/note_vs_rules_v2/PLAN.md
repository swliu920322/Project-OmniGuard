## 0. 先用中文说明这轮要做什么

旧测试同时包含大量数值题与少量备注题。数值规则本来就能计算答案；满分不能证明需要模型，关键词对照较弱也会放大差距。

本轮把研究问题缩小：**在“前方有人或障碍”这个已有话题里，认真完善的规则与固定模型方案，谁更能理解备注？错误、等待时间和费用各是多少？**

例如“刚才有人，现在走了”“没人，但路上有箱子”，要判清当前、否定、历史等关系。不是为了考倒规则而挑偏题，也不把新高分预设为目标。如果完善规则已够用，采用规则或保留规则优先也是有效结论。

这仍是仿真实验，除非取得真实合法来源的使用记录，否则不能称为企业业务验证。没有为了面试证明“必须用 LLM”的预设。

## 2. 比较哪些方案？

| 方案 | 角色 | 允许改什么？ |
|---|---|---|
| R1／R2 | 旧关键词规则，提供历史写法参照 | 原件不动，只复用 |
| R3（新） | 认真改进的确定性规则，主要对照 | 只根据公开开发材料修改，最终测试前冻结 |
| 固定模型方案 | 复用完整 B-1.0 提示词 | 本轮不优化提示词，也不另造“故意弱”的模型基线 |

各方案看到相同字段、相同渲染文本；都输出主要状态 `primary` 与备注判断 `note_status`。R3 先判断备注，再使用相同数值规则合成主要状态；执行动作仍由同一代码合成。主指标比较备注判断，不能用代码纠正后的结果替模型计分。

### R3 怎样才算认真改进，而不是继续放一个弱对照？

实施前写下已知问题与拟处理方式：

- 无主题词的后半句如何承接前句，如“刚才有人，现在走了”。
- 否定、历史、假设、不确定词的作用范围，不能一个否定词否定整句所有情况。
- “没有人，但有箱子”等不同对象与多分句的合并。
- 中英文标点、常见缩写和适度拼写容错；容错也可能引入误报，需要给出反例。
- 不明确信息怎样映射现有六种状态；规范无法裁决的句子进入争议记录，不强行猜答案。

可以使用普通字符串处理、正则和可解释的分句状态规则；不偷偷接另一个模型或外部智能服务。禁止按完整开发句子建答案表、按 ID 返回标签，禁止查看私有旧／新测试输入。

先在公开开发材料上做一版，再允许最多两次有记录的开发修订，随后冻结。这个工作量上限用于避免无限扩词，不声称 R3 是所有规则方法的最好水平。规则篇幅、依赖与修订次数一并报告；若开发阶段仍有明确缺陷，保留并披露，不伪称强基线已充分。

### 新测试（Claude 不看）

- 暂定 **180 条带备注记录**：六种备注状态各 30；每状态中文、英文、中英混合各 10。是平衡实验分布，不代表真实业务发生比例。
- 至少 **60 个不同语义家族**，一个家族最多 3 条；数值变体、改写、翻译不算新家族。家族定义和分组名单在制作内容前承诺。
- 每种状态 15 条配正常遥测，15 条配已有数值风险，并且**状态×语言×遥测三维每格 5 条**（检查器 `per_status_language_telemetry` 逐格检查，不再只分别检查二维），避免只看主标签时掩盖备注错误，也避免语言与遥测被无意关联；物理门控与急停不混入本轮主测试，代码层原有压力证据另列。
- **备注独有停车风险子集** 按检查器的实际定义统计：金标要求停车、但只看遥测不会停车的记录。它由两部分组成：①正常遥测上的“当前肯定／不确定”（按配额应为 30 条）；②遥测只有不会停车的风险（低电量、超速）而备注说有障碍的记录（数量取决于作者选的遥测）。检查器分别报告总数和两部分（`note_only_risk_records`、`…_on_normal_telemetry`、`…_on_non_stopping_risk_telemetry`）。作者交付的候选稿的检查器输出为 42＝30＋12。明确披露这一分母，不能把零漏停解释成可靠性保证。
- 保留常见直接表达、多分句、指代、省略、合理错别字等类型；不得阅读 R3 代码或按其词表漏洞出题，不为凑错而堆极端写法。
- 测试作者只接收规范、覆盖计划及开发样本的家族／重合排除材料，不接收 R3 内部规则、模型预测或模型错误分析；不能承诺他完全不知任务规则。
- 与旧公开例子和开发材料做精确及语义重合检查；所有家族不得跨开发与测试。**旧已用测试已丢失，无法再做逐条去重，这一限制必须在结果里披露，不能写成已隔离；**仍不得把旧样本换数值后算新题，也不得凭记忆重写旧题。
- 备注标签先独立标注，再由新会话先盲标抽样、封存后全量复核。沿用规范 1.0 的盲标比例与最小条数：180 条每状态 30，抽 9 条，共 54 条；披露原始一致率、kappa、分歧与裁决。无法裁决的句子在调用前排除并以同配额补足，留替换原因。

冻结顺序：**R3 与固定模型方案承诺 → 独立测试制作／标注／审计 → 测试哈希与统计承诺 → 运行器与方案绑定检查 → 正式调用。**

缺少独立制作会话时，Claude 可以先完成离线实现并交接，不能自己代出最终测试并宣布独立。用户可提供新的隔离会话，或交由 GPT 保管会话；能力与可访问条件先核实，不凭文档宣称隔离成立。

- 请求前检查调用、token 与金额预算；未知用量保留预留，中断中的请求记账、记录并封存。
- 先用公开开发样本做两次健康调用，不拿测试题做健康检查；健康结果不计正式成绩。
- 健康检查须正常完成，两条均无 API 错误、结束原因正常、严格输出与备注有无相容、输出不超上限、返回别名一致、请求参数符合冻结配置、目录封存校验通过。任一不满足就不启动主测试，不自行换参数重试。

- 自然发生的接口错误、无效回复与截断留在主指标分母计错。另列“有有效回复时的正确率”作诊断，不能用它替换主结果。
- 未发出的用例记 `not_started`；提前停止不能当完整 180 条正式成绩。保留失败，不静默重跑或挑较好一次。
- 模型使用现有配置时不读取或打印密钥；记录配置名、返回别名、声明身份及起止时间，实际版本仍未验证。
- 全部正式结果在预定开发结束后才解封给实施者；测试错误不再用于本轮改 R3 或模型方案。

## 5. 指标与结论怎样预先约定？

### 主要回答

1. 备注状态准确率、各状态召回、备注状态 macro-F1 和混淆矩阵。
2. **模型减 R3 的备注状态准确率差（百分点）**，不是把旧任务 93.67% 当起点。
3. 同一条记录谁对谁错：双方都对、仅模型对、仅 R3 对、双方都错。给原始数量，不能只展示有利样例。

### 重要约束与代价

- 主要状态准确率单列；全部 180 条与正常／有风险遥测子集分开。
- 备注独有风险子集的漏停、全部记录的误停，以及解析失败／API 故障引起的停车。
- 模型全部请求与成功请求的延迟中位数、P95、最大值；分位数算法固定为最近秩法。它是 Router API 请求墙钟，不是 HTTP 业务端到端延迟。
- 已报告用量、未知用量预留、按配置费率估算费用、平均每请求成本；未知用量不当作零，也不称为账单。
- 中文／英文／混合等预定子集报告样本数，避免只挑有差距的子集。

备注准确率差另报告按家族成组抽样的 95% bootstrap 区间：同一轮抽取相同家族，同时计算模型与 R3 差值，保留家族内记录，2,000 次，种子 20261109。这是估计不确定性，不修复合成数据的代表性；按记录的 Wilson 区间可作补充，但不得当家族独立的保证。

本轮是研究对照，不沿用旧“满分即通过”的叙事，不新增任意生产 SLA。没有足够证据说明真实业务可接受多少漏停、延迟和成本，因此不宣布“LLM 必需”。

| 观察到什么 | 可以如何解释 |
|---|---|
| 模型明显少错，关键动作无额外劣化，差值区间支持正向差异 | 在本轮合成备注任务中优于 R3；仍需说明增加的延迟与费用 |
| R3 接近模型或差异不确定 | 暂无足够证据支持模型新增价值；可优先简单方案，不强写提升 |
| 模型少错但更慢、故障／误停更多 | 报告取舍，不能只报准确率 |
| 双方都经常错，或标注分歧大 | 先修需求和规范；不能靠挑题保证一个赢家 |

如果三种方案再次全对，应写“区分度不足或任务简单，无法区分”，不继续看着测试集加难题。

## 7. 第二步架构实验：现在先不做

备注对照完成后，再决定是否比较“一次结构化调用＋代码检查”和“Router→Safety→Compiler＋代码检查”。必须让两边完成同一任务、输出同一最终动作契约，才比较完整记录耗时、正确性、失败和费用；不能用 Router 单段去直接战胜多做两项工作的全流程。

这需要单独计划与预算。当前不改三 Agent、不设计回充工具、不新增视觉，也不预填“延迟降低多少”。

## 8. 完成标准

**收尾只设四个条件，不再增加新任务：**

1. **题目可审查：** 配额、家族、去重和标注复核完成，争议处理有记录。
2. **比较可核对：** 方案测前固定，同题同评分，失败不剔除，不挑成绩。
3. **原件可找回：** 固定目录加独立备份，实际恢复并核对哈希。
4. **交付可复现：** 最终提交包含所需原件，从新克隆能定位并核对；真实模型重跑需自行配置凭据和预算，分数可能变化。

另外，**本地提交不是备份完成**：最后还要确认已推送到 GitHub，并从新的克隆校验交付文件；推送由用户另行授权。

完成意味着：有固定方案、有未用于开发的新测试、有可复核的逐条记录、完整分母、预定指标和清楚结论。**不要求模型赢，不要求准确率提升，不要求简历一定能填一个正数。**

若独立测试、预算或时间条件不满足，停在对应阶段并标明未完成；不能用开发结果充当正式结果。
