# 设计：Safety 和 Compiler 的评测（G5）

2026-11-21。**这是设计，没有实施，没有调用模型，没有改动任何冻结文件。** 对应八关流程第 5 关（系统设计）。

## 1. 主张

正式评测只覆盖路由和规则层。Safety 和 Compiler 两个模型角色已经写好、接在流程里，但**没有任何评测**。本文设计怎样评测它们，并先说清楚评测**能证明什么、不能证明什么**。

## 2. 证据：现在有什么

读了 `embodied_brain/extended.py` 和 `router_v2/pipeline.py`，事实如下：

| 环节 | 做什么 | 出错时 |
|---|---|---|
| Router | 选主要状态和备注状态，代码合并风险；是 HALT 就直接结束 | 回复不合格变成停车（已评测） |
| Safety | 模型看规则和遥测，回答 `PASS` 或 `BLOCK: 原因`；回答以 `BLOCK` 开头就停车 | 异常传到外层，变成 `INTERNAL_ERROR` 停车 |
| Compiler | 模型按模式生成动作 JSON 数组 | JSON 解析失败得到 `None`，交给 `validate_actions` |
| `validate_actions` | 代码检查动作：必须是非空列表、动作在白名单内、停车时只能 `stop`、速度在上限内、`turn` 要有整数角度等 | 有违规就停车，状态 `REJECTED_BY_CODE` |

已有测试（`tests/test_extended_endpoint.py`，全部用假模型）：Compiler 速度超限被代码拒绝、遵守合约的输出被接受、坏输出变成停车、Safety 的 BLOCK 保留决策证据、一个"宽松模型"无法让近距障碍通过整个流程。

**所以：** 代码这一层（`validate_actions`）有较完整的假模型测试；两个**模型**角色本身没有评测数据。

## 3. 推理：该评测什么，不该评测什么

关键观察：**Safety 和 Compiler 只能让结果更严，不能放宽。** Router 的决策（运动、目标、限速、保持项）被保留；Compiler 的动作要被代码对照决策检查。所以模型角色的失误最坏是"多停了"（过度保守）或"生成了一个被代码拒绝的动作"，**不会**放行一个 Router 已经判停的情况。

因此评测应当问的是**可用性和稳定性**，而不是"会不会造成不安全"：

| 问题 | 指标 | 数据 |
|---|---|---|
| Safety 会不会无故拦截？ | 在 Router 不判停、遥测正常的记录上，`BLOCK` 的比例 | 复用已公开的第二轮 180 条中 Router 放行的那部分 |
| Safety 的回复格式是否稳定？ | 回复不以 `PASS` 或 `BLOCK` 开头的比例 | 同上 |
| Compiler 的输出能否通过合约？ | 被 `validate_actions` 接受的比例；各类违规的构成 | 同上，再加覆盖各种动作的构造记录 |
| 重复运行是否一致？ | 同一输入重复请求的结果一致率（注意 `ask_agent` 有 5 秒缓存，必须绕开） | 小样本 |
| 两个模型角色引入多少等待？ | 各自单次请求耗时的中位数和 P95 | 同上 |

**不评测、也不声称的：** 模型是否"真正理解安全规则"；真车安全；制动距离。

## 4. 设计

### 阶段 0：离线、免费（可以先做）

用假模型把"输出的各种坏样子"系统化：对每一类违规构造一个 Compiler 输出，确认 `validate_actions` 都能抓到，并把已有测试按违规类别列成一张覆盖表。目的是回答"代码层能抓到哪几类坏输出"，不是评测模型。

### 阶段 1：真实运行（需要授权）

- 对象：第二轮 180 条中 Router 不判停的记录。按金标，这样的记录有 84 条（96 条金标为停车）；实际进入 Safety 的条数取决于 Router 的真实回复，会略有出入，授权前要重算。
- 每条一次 Safety、一次 Compiler，不重试，故障分类记录；现在扩展流程已经走 `bounded_agent.py`（无缓存、关闭重试、故障分类），评测直接复用它。
- 新建一个像 `no_retry_client` 那样固定超时和重试的客户端，不改冻结文件。
- 预算：约 2 次请求乘以记录数（按 84 条估算约 168 次），具体上限在授权前算出并写进计划；这是估计，不是已批准的额度。

### 阶段 2：报告

按"主张、证据、推理、局限"写；失败留在分母里，不剔除；分家族和分语言列出，像分片报告那样。

## 5. 局限

- 这只能评测**稳定性和可用性**，不能证明安全。真正的安全底线来自代码层。
- 数据是合成的，同一情境三种语言写法，条数不独立。
- 两个模型角色用的是同一个模型和客户端，评测不能说明换模型后的表现。
- Safety 的规则文本来自租户配置；测试用哪个租户配置，结果就只对它成立。
- 没有真实业务期限，延迟数字不能回答"值不值"。
