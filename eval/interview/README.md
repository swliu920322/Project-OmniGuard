# 面试与项目理解材料

这些文件用于理解、讲述和练习，不是新的实验结果。正式数字与局限以 [评测报告](../report.md)、[延迟证据](../LATENCY_EVIDENCE.md)、[证据索引](../EVIDENCE_INDEX.md) 为准。整个 `eval/` 的用途见 [目录导航](../README.md)。

| 阅读顺序 | 文件 | 适合什么时候用 |
|---|---|---|
| 1 | [INTERVIEW_STORY_zh.md](INTERVIEW_STORY_zh.md) | 先理解为什么做；含本人确认的起点、30 秒／两分钟介绍、追问、前端组织习惯及待补分工 |
| 2 | [BACKEND_CODE_GUIDE_zh.md](BACKEND_CODE_GUIDE_zh.md) | 对照源码理解请求入口、三个 Agent、六类判定和风险合成 |
| 3 | [ORAL_EXPLAINED_zh.md](ORAL_EXPLAINED_zh.md) | 不懂术语时看通俗解释，与四行卡逐题对应 |
| 4 | [ORAL_CARDS_zh.md](ORAL_CARDS_zh.md) | 已经理解后快速复习；每题四行：回答、证据、数字、局限 |

建议每次只练一个问题：先用自己的话回答，再查证据，记下不理解的实现细节。文件里的示意例子不是正式测试样本；不要把 AI 写好的回答当作本人已经能解释的证明。

面试主线是“为什么研究云端等待→实际测了什么→为什么补路由评测→代码约束能保证到哪里”。前端封装和 Azure 服务集成作为相关追问展开。个人原始贡献尚不确定的部分保持待补，不编造独立手写经历。

这些文件此前位于 `eval/` 根目录，本次统一移到此处；证据和运行产物没有随之移动。口述验收仍需本人完成。
