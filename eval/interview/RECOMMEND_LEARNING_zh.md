# 学习与面试练习：从理解项目到清楚表达

更新：2026-11-10。目标是支持简历表述、理解项目和准备面试，不设“多少天成为架构师”的身份目标。原学习手册与 GPT／Claude review 中仍适用的方法已合在这里，过时行号、已解决错误和重复评论不再保留。

**配合一份[面试主手册](INTERVIEW_DEEP_DRILL_zh.md)使用：它回答项目问题，这里安排怎样学会。** 不需要先读完书单，不需要新增付费模型调用或为了面试扩建系统。

## 一、先明确你要交付什么

| 目标 | 做出什么 | 怎么检查 |
|---|---|---|
| 简历能落到事实 | 一条项目表述，每个数字和动词有来源 | 对“构建／主导／验证”分别说明本人行动与证据 |
| 理解一次决策 | 一张请求流程图，一个多风险例子 | 找到调用、解析、合成与动作校验的真实函数 |
| 能应对追问 | 30秒介绍、两分钟展开、随机三题 | 不看稿回答，换一个例子还能解释 |

**评语：** 熟悉整篇稿子不等于理解实现；答不出来就回到那一个函数或数字，不继续增加“终极答案”。

## 二、按掌握情况推进，不按读书天数推进

### 1. 输入、状态与动作

先读主手册[第9题](INTERVIEW_DEEP_DRILL_zh.md#q9)；看不懂字段时补[中文入门例子](START_HERE_zh.md)。

- 手写五个数值输入，标注单位；区分 HTTP 名称与内部字段。
- 解释 primary 是主要状态，risk_set 是多个风险，动作是另一个结果。
- 用距离15cm、温度70℃、电量10%的例子，先自己预测主要状态、风险和动作，再看代码。

完成标志：不用术语也能说清“主要问题不等于全部问题”。不会的 Python 字典、条件、函数返回值，按这个例子逐项补，不必先通读语言教材。

### 2. 看懂一次请求

读主手册[第8题](INTERVIEW_DEEP_DRILL_zh.md#q8)和[代码地图](BACKEND_CODE_GUIDE_zh.md)。

- 找到 `/api/simulate_agent` 与扩展租户分流。
- 找到真正发模型请求的位置，区分模型角色与 Python 函数。
- 解释急停和非法输入何时返回，Safety／Compiler 何时跳过。

完成标志：画出一次调用的数据流，指出模型与代码分别做什么。看见注释与代码顺序冲突时，以实现和测试核对，不只背注释。

### 3. 运行一个现有测试，理解一种错误

先读 [REPRODUCE.md](../REPRODUCE.md)，按它准备环境并从仓库根目录运行。例如：

```sh
src/cloud-orchestrator/.venv/bin/python -m pytest tests/test_router_v2.py -q
```

上面的路径适用于当前已有该虚拟环境的工作区；新环境按复现指南创建，不要求机器上天然存在它。

选择一条测试，先读输入、假回复与断言，再运行。解释假模型验证的是处理逻辑，不是模型真实理解能力。无需手动调用模型或注入真实网络故障。

完成标志：自己预测一个坏回复会怎样，能指出对应处理。测试通过不等于所有错误都覆盖，更不等于真车制动成功。

### 4. 手算指标与追查数字

读主手册[数字来源与手算](INTERVIEW_DEEP_DRILL_zh.md#evidence)。

- 分清主要状态准确率、备注状态准确率和漏停次数。
- 自己计算 281/300、23/72，以及它们各自回答什么问题。
- 解释300、55、72、34的来源，说明哪些是配额、哪些是分组结果。
- 运行主手册中的标准库核对命令；说清它读取已有结果，不是重新测试模型。

完成标志：别人追问“这数字从哪来”，能打开文件并指出字段，而不是只报一个文件名。

### 5. 解释延迟与模型价值

读主手册[第2题](INTERVIEW_DEEP_DRILL_zh.md#q2)、[第4题](INTERVIEW_DEEP_DRILL_zh.md#q4)与[第13题](INTERVIEW_DEEP_DRILL_zh.md#q13)。

- 把仿真设定、真实模型调用耗时、浏览器完整往返分开。
- 解释为什么纯数值任务不需要模型，以及备注语义为什么值得比较。
- 给出“如果规则够好，就选择规则”的条件，不预设 LLM 必须胜出。
- 说明当前没有完成单阶段与三阶段的受控架构消融，不能拿不同历史运行拼出收益。

完成标志：既能说已有结果，也能指出影响采用决定的缺失证据。真实机器人、行业标准、导航栈属于可选背景，不是当前项目成果。

## 三、思考：把大问题拆成可以回答的小问题

不要从“云端能不能控制机器人”直接跳到结论。用自己的项目逐步问：

1. 哪个场景？——当前是 AGV 仿真，不是所有机器人。
2. 做什么决定？——当前记录的状态与动作。
3. 等待时怎样运动？——实时仿真按当前速度继续运动；不是已实现本地保护快环。
4. 测到的时间是什么？——模型调用段不等于完整 HTTP 往返。
5. 在给定速度下有什么影响？——速度不变时可估算前进距离，实际避险还涉及其他条件。
6. 什么证据会让我改变判断？——不同任务期限、本地保护、其他模型或更强规则可能改变取舍。

每次先写四句：

```text
我想解决什么？
哪些条件影响答案？
已经知道什么，还缺什么？
什么证据会让我改变判断？
```

## 四、逻辑：检查“所以”是否跳过了条件

| 容易跳跃的说法 | 应补的问题 |
|---|---|
| 两次满分，所以可靠 | 对什么数据？是否真实场景？家族相关性怎样？ |
| 关键词规则漏停，所以必须用LLM | 更好的规则、结构化输入或小模型是否够用？ |
| 请求慢，所以是网络导致 | 有记录区分排队、生成和网络吗？ |
| 代码返回停车，所以车辆安全 | 等待期间发生什么？执行是否及时？硬件测过吗？ |
| 后来能解释架构，所以当时独立设计了它 | 实际是谁提出、谁实现、本人当时作了什么判断？ |

例如：

> 在持续运动、障碍较近、没有本地保护的条件下，若响应超过可用避险时间，可能来不及处理。因此，这类快速避险不能只依赖云端返回，需要另外的保护。保护可以是规则或控制逻辑，是否需要本地模型要另测。

这是一条有条件的推理，不是当前项目已经实现真机保护的结论。30cm也不是由这段话反推得出的硬件安全线。

## 五、表达：回答、依据、例子、边界

> 先直接回答 → 说明依据 → 给一个小例子 → 说明还没验证什么。

被问到范围不清时，可先确认“这里问的是模型分类、后端决定，还是车辆实际运动？”不必机械地每次反问。

示例：

> 我最初想研究机器人持续运动时等待云端模型的时间代价，后来缩小成AGV仿真。现在整理了模型调用耗时，并补了状态路由和冻结评测。比如准确率回答判断是否正确，耗时回答是否可能赶上任务期限；两个问题要分开。当前没有真实车辆控制或浏览器完整往返的验证。

这是表达示例，动机与分工仍由本人确认。逐步补上的方法，不说成最初就全部规划好了。

## 六、每天10～20分钟，先自己回答

起步不必一次做全：

1. **自己写5分钟**：不看稿、不用AI，只选一题。
2. **录音约60秒**：先说结论，再说依据、例子与边界。
3. 能稳定做后，加上**标来源**：代码／记录／推测／计划；自己的经历另标本人回忆。
4. 回听只改一个问题：没回答、缺例子、无证据，或混淆指标。圈出没有依据的“绝对、必定、唯一、铁证”。
5. 需要时请AI每次只追问一题，最后由自己重新回答。不是让它代写更漂亮的稿子。

先练这一题：**我最初想研究什么，现在的项目实际回答了其中哪一部分？**

给AI的要求：

```text
先让我回答，不要直接提供标准答案，每次只追问一个问题。
指出概念不清、推理缺条件、证据不足或没有直接回答的位置。
项目事实需要给出可核对的文件和字段；没访问材料就说无法核实。
解释后让我用自己的话再说一次，不把新理解写成我过去已经完成的决策。
```

## 七、怎样知道自己提高了

- 不看稿也能讲清，能换一个例子解释相同规则。
- 被问为什么，能给依据，不只是换一套术语。
- 说不知道时，能说明怎么核对。
- 简历的一句话能展开成具体行动、代码行为、结果和限制。
- 能发现AI解释中的一个错误，而不是只比较哪份语气更专业。

仍卡住就回到对应步骤，不用靠读完更多书证明进度。课程和书按实际问题选读，查课程版本和章节，不设强制书单或高级岗位承诺。

## 八、接下来只做三件事

若还不确定目标岗位，先看[职业路线](CAREER_ROADMAP_zh.md)，选择方向后再补最相关的一项能力，不把所有技术同时设为必修。

1. **简历目标**：确定一条有证据支持的项目描述，补本人真实分工。
2. **项目理解**：画流程、读函数、运行一个测试、手算一个指标。
3. **面试练习**：练30秒与两分钟介绍，再随机三题；把新的理解写回主手册同一题。

本轮不自动启动新研究、真机接入、部署或付费评测。原始结果和局限仍以[正式报告](../report.md)、[延迟证据](../LATENCY_EVIDENCE.md)、[证据索引](../EVIDENCE_INDEX.md)为准。历史学习稿和审阅记录保存在 Git 提交 `3895efb`，不再作为当前待办清单。
