## 二、事实问题(按重要性)

### A1. "34 例 floor_override"数字不对,解释也不对
- **位置**:355、483 行。
- **事实**:公开摘要里模型方案的 `floor_override` 是 **70/300(0.2333)**;R1 是 72,R2 是 77。手册的 34 找不到来源。
- **解释也错**:手册说是"模型漏判或被虚假便签误导,被代码纠正"。按 `rules.py:181-227`,`added_risks` 只要有一个遥测风险不在模型回复所指出的风险里就算,而模型的 `primary` 只能给出一个主标签。所以多风险记录(例如既低电量又过热)里,模型只说对优先级最高的那个,代码补上另一个,也会计入。这和"模型被骗"不是一回事。我没有逐条核对这 70 条的构成,所以只能说"不能解释成漏判"。
- **483 行"100% 挽救大模型漏判"**同样不能说。
- **改法**:数字改成 70/300,说明含义是"代码补进了模型回复没有覆盖的遥测风险",并写明没有逐条归因。

### A2. 把"设想"和"没有的记录"当事实讲

### A3. 场景 3(宕机 60 秒)说过头了
- **位置**:506–513 行。
- **问题**:
  - "绝对不会卡死""保障了绝对安全"是绝对化。

## 三、没做到你提的要求

你要的是:**人类角度 → 任务拆分 → 细节 → 回到代码演示和实操 → 组装,并保持整体-入栈-细节-出栈-整体。**

### B1. 缺"任务拆分"这一层
第二层的车间故事直接跳到第三层的函数调用栈,中间没有"把这件事拆成几个小任务"。外行读到 Frame 1~8 时,不知道为什么是 8 个。
**建议**:在两层之间加一小节,用人话拆成四个问题:
1. 这份报告靠谱吗?(Frame 3、4)
2. 便签说了什么?(Frame 5、6)
3. 数字说了什么、两者冲突听谁的?(Frame 7)
4. 最后发给车的动作合理吗?(Frame 8)
再在每个 Frame 开头写"这是四个问题里的第几个"。

### B2. "代码演示和实操"没有真正跑项目代码
- 八个 3 行片段和第五层的整合脚本**都是重新写了一遍逻辑**,没有 `import` 项目里的函数。第五层是自己判断自己。
- Frame 5 的片段用 `MagicMock` 先设定返回值,再打印它,**测的是 mock**,不是 `no_retry_client`。
- Frame 7 的 `override = (tele_risks != model_risks)` 与真实代码 `bool(added or forced_by)` 不同,会在边界情况上给出不同答案。
- 因此"实操验证"并没有验证项目,还容易把读者带向与代码不一致的理解。
- **改法**:每个片段改为真实调用。例如 Frame 3 用 `from router_v2.rules import check_input`;Frame 7 用 `execute()` 加一个假的模型回复;Frame 5 用 `no_retry_client` 配一个有 `with_options` 的假客户端;第五层用 `decide(rec, note, fake_call)`,不联网。
- 这同时是最好的"实操":读者看到的就是项目里的真输出。

### B3. "出栈回归"只在面试话术里,没有成为每帧的收尾
每个 Frame 的"出栈"只是话术里的一句,没有回到整体图上标"现在走到了哪里、下一步是什么"。
**建议**:每个 Frame 末尾固定写 1~2 行:"刚才这一步在整条路上的位置(第 x/8),如果它出错,最坏结果是……,下一步交给……"。开头固定一行:"这一步回答第几个问题"。这才是"整体—细节—整体"。

### B4. 面试话术段落会让读者背稿
五个字段里的"面试标准话术"是现成答案,且大量带夸大语气("纳秒级""比特级""绝对")。你的目标是能解释,不是背诵。
**建议**:改为"我想说的"四句式:结论、依据、范围、没验证的,并标注哪些是事实、哪些是设想。
